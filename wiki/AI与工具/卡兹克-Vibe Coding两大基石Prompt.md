## 一句话总结

**Vibe Coding 只要记住两个词：第一性原理（管生成）+ 对抗式审查（管验证）。** 前者保证 AI 写出对的方案、找到 bug 的根因；后者保证代码能稳定上线。两者构成一个完整闭环，是作者近一年 Vibe Coding 每天说的最高频词汇，也被称为"神之 Prompt"。

---

## ① 第一性原理（管生成）

### 用法
不用装 Skill、不用写 System Prompt，**在你平时说话的末尾加一句"从第一性原理出发"** 即可。修 bug、设计方案、做架构时都适用，任务越复杂越万能。

### 原理
现在的 AI 多数还在做**类比推理**：你说"写一个过滤函数"，它会在训练数据里找到几万个类似的，给你一个"看起来差不多"的。快、能用，但跳过了最关键的步骤——**"这个问题真的应该这么解吗？"**

"从第一性原理出发"这七个字，做的就是**强制打断 AI 的类比推理**，逼它回到问题本质、从最基本的事实出发重新推导，不参考别人的方案。

### 实例：AIHOT 流量路由事故
- 表象：OpenAI 官网信源断了三天没被抓取，Agent 说"是之前测试国产模型时把 OpenAI 抓取改坏了"，建议单独修好。
- 加一句"根据第一性原理来找一下原因"后：发现是**流量路由层面的底层隐患**（4 月写的代码），表层小错只是把它暴露出来。若只做表面修复 = 缝补破船最后堆成屎山；从第一性原理出发直接重构底层路由 = 治本。

### 经典思想
亚里士多德两千多年前就说过；马斯克用于 SpaceX——行业共识"火箭发射要花几个亿"，他重新从原材料成本算起（铝合金、碳纤维、航空燃料），最后发射成本降了 90%。GitHub 已有 `first-principles` skill，但作者认为直接加一句口头语就够。

## ② 对抗式审查（管验证）

### 用法
开发完的测试流程，让 AI 站在**恶意用户/对手**的角度找茬。Claude Code 场景："开启 Ultracode（动态工作流，N 个 Agent 并发）来对之前开发的功能进行对抗式审查"；Codex 直接说"开启多 Agent 帮我进行对抗性审查"。

### 原理
AI 写代码漏洞多，光靠"帮我看看有什么问题"远远不够。对抗式审查的核心是换一个立场：**"如果我是一个恶意用户，我会提交一个 50MB 的 HTML 来搞崩你的 worker。"**——从入口到崩溃把整条路径走一遍，把所有奇怪边界都想全。

### 实例（AIHOT 一次大审查，近 40 个 Agent 并发）
- **OOM 死循环**：后台 worker 处理超大任务时内存爆掉被杀 → 自动重试 → 又爆又杀，无限循环。恶意用户视角立刻暴露这个缺口。
- **未来时间污染**：某信源文章因时区错误发布时间显示为"未来"，会排到精选信息流最前面、进入飞书 PUSH 和 RSS、日报置顶——**一篇来自未来的文章污染整个信息流**。这种 bug 自己写代码根本想不到。

### 节奏建议
- 常规开发：每次测试流程都用对抗式审查。
- 每 2–3 周：对整个项目做一次**从第一性原理出发的全局对抗式审查**——从最底层原理出发并发审查架构、依赖关系、代码质量、文档对应；顺带测试新模型能力、review 近两三周功能，"每次都能挑出之前没注意到的技术债和潜在风险"。

## 应用远不止 Vibe Coding

这两个思维习惯跟具体领域无关，只是代码领域格外好用：
- **写文章**：让 AI 对抗式审查逻辑漏洞、事实准确性、论证力度——比"帮我看看这篇文章怎么样"有用太多。
- **商业方案**：让 AI 从第一性原理剥掉所有假设，质问核心逻辑是否成立。
- **人生决策**（如"要不要换工作"）：先第一性原理想清楚自己到底想要什么，再对抗式审查让 AI 专门找思考盲点和你下意识回避的风险。

---

## 金句

> "第一性原理的核心就一句话：回到最根本的事实重新推导。"

> "对抗式审查的核心也就一句话：你永远需要一个站在你对面的力量来告诉你，你可能是错的。"

> "这两个词加在一起构成了一个完整的闭环……是 Vibe Coding 的两大基石，并肩站在一起的那种。"
