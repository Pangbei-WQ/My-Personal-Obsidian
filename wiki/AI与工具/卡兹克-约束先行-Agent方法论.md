## 一句话总结

**在让 Agent 干任何事情之前，先把规范定好——全局的规矩、项目的规矩、文件夹的规矩，规矩从上往下穿透、一层套一层，没有规矩的地方不动手。** 卡兹克认为这四个字"比一切 Prompt 技巧都重要"。

---

## 核心洞察

> **"对于 AI 来说，你脑子里知道的东西，如果没有写进文档，就是不存在的。"**

- Agent 的短期记忆会丢失，对话框一关全忘，下次只能看到你留下的文档和记忆文件
- 文档是否清晰，直接决定 Agent 每次"醒来"是清醒的还是懵的
- 这解释了为什么有的 Agent 越用越蠢——规范和记忆体系是"屎山"

---

## 三层/四层约束体系（以 Claude Code 为例，Codex 等类似）

| 层级 | 载体 | 类比 | 作用 |
|------|------|------|------|
| **最顶层** | 全局 `CLAUDE.md`（用户目录，打开任何项目都加载） | 宪法 | 你是谁、做事原则、协作方式 |
| **第二层** | 项目级 `CLAUDE.md`（进入某项目才加载） | 项目基本法 | 目录结构、命名规范、文件放哪 |
| **第三层** | 项目内规范/设计/架构文档 | 部门规范 | 具体操作指南 |
| **最底层** | 记忆文件（Auto Memory、对话记录） | 员工笔记 | 执行层记录 |

> 类比：治理公司——制度在最上面，部门规范在中间，具体操作在最下面。**不能靠 CEO 每天挨个盯着员工干活，靠的是制度穿透下去。**
> 类比：玩《城市天际线》——前期最重要的不是赶紧建建建，而是先把路网规划好。**CLAUDE.md 就是你的路网。**

## 作者全局 CLAUDE.md 的结构（可直接参考）

卡兹克公开了自己的全局 CLAUDE.md，核心模块：

1. **关于我**：虚实传媒创始人、UX 设计师出身不是程序员、用 Claude Code 做"开发产品 + 知识管理"两件事、哲学是"把任何重复 3 遍的事 AI 化或自动化"
2. **第一性原理**：所有决策从问题本质出发，不因惯例照搬；**不要谄媚**（不夸想法好、不说"这是个很好的问题"、不加"当然可以"）；方案有问题直接指出
3. **约束先行**：新项目先写 CLAUDE.md、新目录先定结构约定；没有规范不动手；**需要调整规范时先改文档、再改实践**
4. **交互设计原则**（作者 UX 出身）：为目标设计不为功能设计；不要让用户思考；系统承担复杂性；渐进式展示；反馈引导行动
5. **工作方式**：默认中文、代码用英文；结论先行再给理由；不要问"你确定要这样吗"除非有真实风险
6. **开发习惯**：改完主动跑验证（test/lint/build）；不靠注释掉报错掩盖问题；密钥不进代码
7. **Git 与部署**：commit 用英文；git push 仅用于跨设备同步

## 关键规则

- **"先立法，再执法"**：AI 发现规范不合理，必须先改文档更新规则，再按新规则执行，避免无法追溯的临时变更
- **反谄媚是沟通约束**：AI 觉得方案有问题必须直接指出，不许拍马屁
- **顶层约束优先解决"身份一致性"**：有了"宪法"，AI 进新项目不会每次从零犯同样的错
