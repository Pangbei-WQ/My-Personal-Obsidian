## 一句话总结

**长程 Agent 跑偏的根因，是你目标定义得不够清楚。** 卡兹克开源了 `Leader.skill`（含"目标七问"方法论），把人类脑子里模糊的需求，变成一份能交给 Agent 用 `/goal` 目标模式独立执行几小时以上、且保证完成度的目标任务书。核心心法：**一个目标里，Harness（禁止项/边界）比 Goal（方向）本身更重要。**

---

## 背景：交互范式的转变

- **聊天制**（问一句答一句）→ **任务制**（Coding Agent 做一个功能）→ **目标制**（2026 年起，Claude Code / Codex / Kimi Code 的 `/goal` 目标模式）
- 目标制下，人类只验收，不盯着执行
- **致命问题**：短任务跑偏还能临场纠正；长程任务跑偏，睡醒它已沿错误方向狂奔 8 小时——"越勤奋，浪费得越彻底"，作者一天浪费过 **20 亿 Token**

## 两个关键概念

### 1. 指挥官意图（Commander's Intent）
来自军事传统：告诉部队"**为什么打**"和"**打完了战场该是什么样**"，然后让他们自己决定怎么打。
- 例：说"过桥清扫高地"，桥被炸部队就傻了；说"掐断补给线"，桥没了它自己会绕路
- → 给 Agent 目标同理：**意图不变，手段随机应变**

### 2. Harness > Goal
- **Goal 告诉 Agent 往哪走，Harness 告诉它哪些路不许走**
- 定义目标最重要的部分，不是告诉它要做什么，而是告诉它**什么不能做**
- 普通人定目标写"想要什么"；大佬定目标先想"达成这个数字最偷懒的办法是什么"，然后把偷懒路径全堵死，剩下的才是目标
- 肯尼迪登月宣言的关键在"**并安全带回地球**"——把"单程票"这个最省钱的解法直接删掉
- 芒格："我只想知道自己会死在哪里，这样我就永远不去那里。"

## 目标七问（Leader.skill 核心心法）

用"出海"打比方——给 Agent 定义目标就是派一艘船出海，船在海上怎么兴风作浪你管不着，所以出航前必须想清楚七件事：

| # | 维度 | 出海类比 | 要问自己的 |
|---|------|----------|-----------|
| 1 | **目的 Why** | 为什么出海？找香料/探航线/打仗？ | 不写清楚，船遇岔路不知道咋整 |
| 2 | **完成态 Done** | 船回港甲板上该有什么？ | 具体到靠岸那一刻就能判断的程度（带回三船香料才算） |
| 3 | **证据 Proof** | 谁来清点货舱、怎么算数 | 不能听船长说满就是满，得有人一箱箱点过 |
| 4 | **反作弊 Anti** | 不许抢商船凑数 | 把偷懒路径一条条写明白，告诉它不许这么干 |
| 5 | **边界 Bounds** | 只许走这三条航线，粮食 30 天第 20 天没找到就掉头 | 明确禁区与硬性截止条件 |
| 6 | **取舍 Trade** | 风暴里保货还是保船 | 提前说优先级，否则它只能猜，猜错整趟废 |
| 7 | **未知 Unknown** | 海图空白区怎么办 | 不要硬闯也不要原地抛锚——记下来绕过去继续走 |

## 使用流程

1. 选一个规划模型（如 Claude Fable 5 / Kimi K3），把模糊需求丢给它，触发 Leader.skill
2. Skill 先对文件库实测/联网调研 → 问你最多 5 个必须由你拍板的问题（如"为啥看不懂？"）
3. 基于目标七问生成目标任务书（约 12 分钟）——有定义、有界限、有现状、有规矩、有完成条件
4. 把目标任务书交给执行模型：`/goal` 模式 + worktree，用 Opus 5 High / GPT-5.6 Sol / GLM-5.2 等长程执行
5. 作者推荐组合：**Fable 5 规划 + GPT-5.6 Sol 执行**（最经济、最大化两家 Token 额度）；国产可用 Kimi K3 规划 + GLM-5.2 执行
6. 额外场景：公司管理、市场策划、运营方案，给足上下文也有奇效
