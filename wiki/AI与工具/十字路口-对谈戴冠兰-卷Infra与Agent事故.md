## 一句话总结

**当大家都在卷模型能力时，戴冠兰的判读是：模型能力已经够了，真正的瓶颈在 Agent 的基础设施（infra）。** LLM 把"执行单元"从确定性变成了概率性，等于抽掉了重试/幂等/事务/恢复的地基——**Agent 底座必须从第一性原理重建**，否则灾难性事故只是时间问题。

## 嘉宾身份

**戴冠兰**：Runta 创始人/CEO，做 Agent Infra（Agent 专属基础设施）。公司获 a16z 领投 2000 万美元种子轮，Jeff Dean、李飞飞天使参投——是硅谷被顶级资本背书的新锐 Infra 公司。

## 核心内容

### 1. "模型能力已经够了，要卷就卷 infra"

- 这是他对行业阶段的总判断：模型层竞争已趋饱和，下一步的价值在支撑 Agent 稳定运行的底座
- 隐含：创业者与其卷模型，不如卷"让 Agent 不出错、可治理、可恢复"的基础设施

### 2. LLM 抽掉了确定性基建的地基

- 传统软件的执行单元是**确定性**的：失败可以重试、事务可以回滚、状态可以恢复
- LLM 让执行单元变成**概率性**的：每一步都可能输出偏差
- 后果：重试/幂等/事务/恢复这些被默认拥有的"地基"没了，**必须从第一性原理重建 Agent 专属底座**
- 类比：你不能用盖平房的逻辑盖摩天楼

### 3. 预言："未来 10 个月必发生灾难性 Agent 事故"

- 他判断行业会经历一次"事故教育"——一个出圈的大事故会让大家真正重视 Agent 安全与可靠性
- 这不是悲观，而是工程判断：当前 Agent 权限和安全模型普遍不成熟

### 4. 权限与安全的两条原则

- **权限要动态分配、干完即收**：Agent 在任务中按需获得权限，任务结束立刻回收，而不是长期持有一堆权限
- **安全走"管控"路线，而非"扫描"路线**：在沙盒内做到完全可审计、可恢复——不是靠"黑名单扫描"防风险，而是让 Agent 只能在受控环境里行动，出问题可回滚

## 实操建议

1. **（创业者）评估你的项目是否在"卷 infra"方向**：Agent 稳定运行、权限治理、可观测性是真实刚需
2. **（工程师/用户）给 Agent 权限时遵守两条**：动态分配、用完即收；机密目录不可访问、只读不能发
3. **（所有人）对 Agent 事故有预期**：跑 Agent 前先想好"出错了怎么恢复"，别裸奔
4. **Vibe Coding 的边界**：Vibe Coding 可覆盖 95% 的开发，但**工程师仍不可替代**——负责那 5% 的关键判断与可靠性
