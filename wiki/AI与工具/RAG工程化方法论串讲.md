# RAG 工程化：从"检索增强"到"知识调度系统"（专题串讲）

## 为什么串讲这三条来源

三条内容来自不同作者、覆盖不同颗粒度，但讲的是**同一个系统的三层**：

| 来源 | 颗粒度 | 它回答的问题 |
|------|--------|-------------|
| **《RAG向量库实战讲透》** | 系统全貌 | RAG 的**工程骨架**：入库链路 + 问答链路 + 落地四层架构 + 五条经验 |
| **《12个AI热词》** | 概念词典 | RAG 背后的**底层机制**：Embedding、向量数据库、Context Engineering、Harness、Loop |
| **《AI+知识库工作台》（姜胡说）** | 用户侧视角 | RAG 之上的**知识组织**：目录怎么建、AI 怎么"知道该查哪份文档" |

合起来才是一套完整的 **企业知识调度系统**：`知识怎么组织（姜胡说）→ 资料怎么被检索（RAG 工程）→ 底层靠什么原理（12 热词）`。这正是串讲它们的理由。

---

## 核心论点（一句话）

> **RAG 不是"文档进向量库 + 接个模型"，而是一条完整的知识流水线——资料进来要清洗/切块/向量化（入库），提问出去要理解/检索/重排/组装（问答）；真正的工程难点全在中间层，且必须配权限前置 + 反馈评测才敢上线。**

## 互证点详解

### 1. "RAG = 先检索再生成"——两条来源互相印证

- **RAG 视频**："RG 说白了就两步，先检索再生成。检索先从知识库里找相关资料，生成让模型基于这些资料组织答案。"
- **12 热词**："RAAG 的思路是，先把资料放进知识库，提问时系统先去知识库里找相关内容，交给 AI，最后基于这些资料回答……这就不是瞎编，而是基于资料回答。"
- **印证**：两者对 RAG 的定义完全一致，且都强调同一个动机——**大模型不知道公司资料、不知道最新变化、不会编却偏要编**。RAG 视频补充了更严苛的工程视角：**难点不在接模型接口，而在中间那一层**（切、存、搜、排、塞、判）。

### 2. 向量化的边界：Embedding 的"语义相似" vs 精确条件的短板

- **12 热词**给原理："Embedding 就是把文字变成一串数字，计算机比较数字之间的距离。'怎么申请退款'和'订单取消后钱怎么退'字面不同但意思接近，变成向量后系统能判断语义相似。"
- **RAG 视频**给边界："向量搜索很擅长找语义相似，但**不擅长处理版本号、日期、部门权限、产品线、地区、合同类型这些精确条件**，所以真实工程里要做**混合检索**：向量搜语义 + 关键词搜精确 + 元数据过滤。"
- **印证**：12 热词解释了"为什么向量搜索有用"，RAG 视频解释了"为什么向量搜索不够用"——两者合起来才是完整的检索设计。

### 3. Context Engineering：12 热词的概念 ↔ RAG 视频的"上下文组装"

- **12 热词**："Context Engineering 的核心不是给 AI 更多信息，而是给 AI **刚好需要**的信息。太少了判断不准，太多了被干扰，过期了会出错，权限没管好会泄露。"
- **RAG 视频**："上下文不是窗口越大越好。要给模型三页精准资料，而不是 300 页合同。要区分三种上下文：**及时上下文**（当前对话）、**检索上下文**（知识库资料）、**用户画像/长期记忆**（个性化背景）。"
- **印证**：这是两条来源重叠度最高的概念。12 热词从原理上定义"信息流设计"，RAG 视频给出可直接落地的**三分法**。RAG 视频还加了 12 热词没讲的实操细节：**要求模型引用来源**（文档标题/更新时间/链接），让答案可追溯。

### 4. Harness ↔ "权限必须前置"：同一原则的两个表述

- **12 热词**："Harness 就是给 Agent 套上安全带、方向盘和刹车——权限控制、工具白名单、执行沙箱、审计追踪、人工审批……企业需要的不是聪明的 Agent，而是安全可控可追踪能被验证的 Agent。"
- **RAG 视频**："**权限必须前置**，不能等 AI 回答完再过滤。如果用户没权限看某份文档，那这份文档从检索阶段就不应该被召回。"
- **印证**：12 热词讲的是通用 Agent 治理，RAG 视频把这一原则**收敛到检索环节**——比"回答后过滤"更早、更省、更安全。这是企业知识库特有的 Harness 落地点。

### 5. Loop/评测 ↔ 反馈层：知识库不是搭完就结束

- **12 热词**："Loop 就是自动导航与纠错系统——目标拆解、自检复盘、自动重试、达标判定。"
- **RAG 视频**："一个知识库不是搭完就结束了，要不断调切块、调召回、调排序、补资料、改提示词。要有**评测集**：收集 50–200 个高频真实问题，每次改切块策略/换 embedding/换 rerank/改 prompt 都跑一遍，看准确率、召回率、引用正确率、拒答正确率。"
- **印证**：RAG 视频把 Loop 工程化成了**可量化的评测闭环**——不是"让 Agent 自查"，而是用标准答案集做回归测试。这正是"从拼系统安全走向拼任务闭环能力"在企业知识库场景的具体化。

## 与姜胡说工作台的互补：知识组织 × 检索工程

> 本表为 LLM 综合判断，未经人工审核。

姜胡说讲"知识怎么组织"，RAG 视频讲"组织好的知识怎么被检索"，两者是上下游关系，互不冲突且缺一不可：

| 维度 | 姜胡说（知识组织） | RAG 视频（检索工程） | 合起来的系统 |
|------|-------------------|---------------------|-------------|
| 核心动作 | 目录建得好，AI 知道该去哪找 | 资料切得好、索引建得好，AI 能搜得准 | 知识调度系统 |
| 资料入口 | 灵感库 → 分类进项目/资产/资源/归档 | 清洗 → 切块 → 向量化 → 入库 | 一条完整流水线 |
| 权限意识 | 明确区分"你的"与"外来的"（资源库） | 权限前置，没权限的文档检索阶段就不召回 | 权限贯穿组织 + 检索 |
| 反馈机制 | 代办项跟踪、AI 越用越懂你 | 评测集回归、反馈层持续调优 | 组织 + 检索都闭环 |
| 一句话 | "知识不是用来存的，是用来查自己的" | "核心指标不是答得多像人，是答得能不能被验证" | 知识库 = 可查 + 可验证 |

**关键洞察**：姜胡说把"告诉 AI 每个目录的用途"当作让 AI 路由的钥匙——这在 RAG 术语里就是**元数据（业务线/权限/时间）驱动检索**。他不是在讲另一个系统，而是在讲 RAG 系统"数据层"的用户侧经验。反过来，RAG 视频提醒姜胡说的做法要成立，必须补上**切块质量 + 检索排序 + 评测**这三块工程，否则"AI 知道该去哪找"也会因搜不准而失败。

## 深化：RAG 四层架构 × 本 vault 的落地对照（LLM 综合判断）

> ⚠️ 以下为 LLM 推断，未经人工审核。

RAG 视频的"落地四层架构"与本 vault（Karpathy LLM Wiki）高度同构——本 vault 事实上已经是这套架构的一个小规模实例：

| RAG 四层 | RAG 视频的工程要求 | 本 vault 的对应物 |
|----------|-------------------|------------------|
| **数据层** | 过期/草稿/权限不清的不进，重复合并、冲突标记 | `raw/` 只读 + 只存有来源资料；`review_status` 审核状态 |
| **索引层** | 向量/关键词/元数据三种索引 | `wiki/index.md` 领域索引 + `sources:` 溯源 + tags 分类 |
| **推理层** | 约束不瞎编、标来源、高风险不直接下结论 | `AGENTS.md` 来源至上原则、`🔍综合判断`/`💡LLM推断` 标注、权限表 |
| **反馈层** | 记录反馈、评测集回归 | `wiki/log.md` 操作日志 + Lint 健康检查（矛盾/过时/孤儿页） |

**本 vault 可借鉴的 RAG 工程增量**（尚未落地）：

1. **语义检索**：目前本 vault 靠 `wiki/index.md` + 双链人工组织检索，可考虑给 `raw/`/`wiki/` 加**向量索引**，让"意思接近但关键词不同"的查询能命中。
2. **评测集**：可把"50–200 个高频问题 + 标准答案"的想法引入 Ingest——每次改 `AGENTS.md` 或页面结构后，用固定问题集抽查可追溯性。
3. **元数据过滤**：`review_status`、`date`、`tags` 已是元数据雏形，若未来量大了可按"审核状态 × 更新时间"过滤检索结果，实现"过期知识不进答案"。
4. **rerank 意识**：回答用户查询时，"先给结论 + 依据 + 来源"的排序，本身就是一种手工 rerank——优先给可验证的高质量来源。

## 可操作清单（把三条来源落成一套方法）

1. **先选高频低风险场景**（研发问答 / 客服知识库 / 代码问答），别一上来做"全公司大脑"。
2. **数据层做减法**：过期、草稿、权限不清的不进库；重复合并、冲突标记；保留标题层级/时间/作者/权限/业务线元数据。
3. **切块按语义不按字数**：一个完整小主题放同一 chunk，块太大/太小都会坏。
4. **检索用混合式**：向量搜语义 + 关键词搜精确 + 元数据过滤（权限/时间/业务线）；向量搜索不擅长版本号/日期等精确条件。
5. **问答链路先理解再检索**：缺关键信息先追问；检索后 rerank 精排（不是越多越好）；组装上下文时区分问题/资料/规则/优先级。
6. **答案必须带来源**（文档标题/更新时间/链接），可追溯才有信任；权限前置，没权限的文档从检索阶段就不召回。
7. **用评测集做回归**：50–200 个高频问题 + 标准答案，每次改动跑准确率/召回率/引用正确率/拒答正确率。
8. **知识组织借鉴 PARA**：目录清晰 + "把每个目录用途讲给 AI"，让 AI 知道该查哪份文档——这是检索系统之上的"路由层"。
